## 📌 2. カテゴリ別の増減理由（すべて実コード・実測が根拠）

### 主要業務フロー 33% → 35%（+2）

- ウォッチリスト UI（`#163`）が画面から使えるようになった（`src/app/watchlist/page.tsx`）
- 本サイクルは新規業務機能を追加していない（全件が不具合修正）

**依然として欠けているもの**（product 監査で実コードから確認）:
施工可否判定の履歴閲覧手段が無い（`v1/decisions` は POST のみ）/
現場（ConstructionSite）を編集・削除できない（GET・POST のみ）/
承認フローがモデルごと存在しない / 通知の外部配信チャネルが 0 件。

### 必須機能 48% → 50%（+2）

- ウォッチリスト UI
- 本サイクルの修正は既存機能を**壊れにくく**したが、機能を増やしてはいない

実測: PWA `public/sw.js`(120行) + `manifest.ts` あり。Excel は実 OOXML `.xlsx`。
**PDF は「印刷用HTML」**（`report-export.ts` が `contentType: text/html` を返す）。

### UX 60% → 62%（+2）

- 公開レビュー環境 `codip-mvp` が稼働し、外部から触れる状態になった
- 本サイクルに UX 作業は無い

**本サイクルで解消**: `AppHeader.tsx` の `VIEW_META` に6ルートが無く、
`/terrain` `/weather` `/sites` `/decisions` `/reports` `/watchlist` で
ヘッダが「🏠 ダッシュボード」と誤表示されていた（`metaFor()` が該当なしで
`VIEW_META[0]` へ落ちるため、画面は壊れず誤ったタイトルだけが出る）。
PR #183 で6件を追加し、サイドバーとの対応を契約テストで固定した。

**未解決**: 実装済み API 17本が UI 未接続（`assessments/point` 187行・
`assessments/geometry` 191行・`records/point` 171行・`recommendations`・
`analysis/wave50`・`analysis/historical` など、約700行の実装が画面から到達できない）。

### データ連携 79% → 81%（+2）

- **取得失敗が `success` として記録される欠陥を解消**（`#175`）。
  HTML を CSV と誤判定する経路と「全件スキップでも success」を塞いだ。
  これはデータ連携の**信頼性**そのものであり、件数より効く
- seed のデータソースは 95 件（50種の目標を超過）

### セキュリティ・監査 82% → 88%（+6）— 本サイクルの主戦場

本サイクルで解消:
RBAC 主体の偽装による権限昇格 / ロール経路の CSRF 欠落 / 内部ヘッダーの素通し /
未認証 GET の未捕捉 500（3ルート）/ 空間評価の未認証 DB 枯渇 /
Workers OOM 経路 3件 / ILIKE ガードの自明な回避 / 依存脆弱性 high 2件 /
認可拒否経路の契約テスト 15件（**認可を全削除しても既存テストは緑だった**）。

08-13 の既マージ分: 全コネクタのホスト検証、CodeQL sanitizer 3系統。

**満点にしない理由**: Cloudflare Access JWT の署名検証が未実装で、
信頼境界がヘッダの存在に依存している。監査ログの `actor` が
`"管理者" | "システム"` の2値固定で、**誰が操作したかを原理的に復元できない**
（ロール付与すら `GRANTED_BY = "admin"` 固定）。公共調達の監査要件を満たさない。

### 運用保守性 72% → 76%（+4）

加点:
インシデント Runbook を実行可能化（コードフェンス 0→18）/
**動作しない MVP 復旧コマンドを発見・修正**（`wrangler rollback` の引数誤り）/
SLI/SLO・RPO/RTO を実装と実測から定義 / SLA 監視の 403 を修正
（**10回中0回成功だった**）/ バックアップ失敗の通知経路を追加 /
デプロイ素性ゲート（**作業ツリーをそのまま本番へ出せた**）/ 段階的デプロイ計画。

減点要因:
**バックアップが 2026-08-13 から失敗中**（Secrets 未登録の fail-closed）。
本評価の判定基準は「バックアップが揃って初めてカバー済み」であるため、
これが解消するまで運用保守性は 80% に届かない。
`pg_restore` 型の復元訓練は一度も実施しておらず、暗号化 dump の復号可否も未検証。
