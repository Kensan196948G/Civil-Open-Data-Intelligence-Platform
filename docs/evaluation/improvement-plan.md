## 6. AI設計方針（追加導入時の要件）

### 6.1 原則
- 🤖 AIは「時間削減・検索・判断支援」に限定し、**施工可否・安全性・法令適合を自動確定しない**
- 📚 根拠・引用・信頼度を必ず表示し、人間承認なしに業務判断へ接続しない
- 💰 利用量・予算上限・停止手段を実装してから導入する

### 6.2 機能別のAI要否

| 領域 | 手段 | 理由 |
| --- | --- | --- |
| データ検索 | RAG＋構造化検索 | 自然文から該当データ・根拠URLを提示 |
| 判定支援 | ルールエンジン＋AI参考解説 | 判定本体はルール、AIは解説・注意点のみ |
| 品質監視 | 異常検知（統計＋AI） | 更新停止・急変・欠測パターン検出 |
| 文書処理 | 構造化抽出 | 公開仕様・図面・PDFから項目候補抽出 |
| 分類・要約 | ルール優先＋AI補助 | 誤分類リスクを低減 |
| 予測（気象・工期） | 将来課題 | 精度検証と責任分界の設計後に限定利用 |

### 6.3 必須設計項目

| 項目 | 要件 |
| --- | --- |
| モデル構成 | 外部API利用時のデータ最小化（公開情報のみ）、自社機密情報を入力しない |
| 根拠・引用・信頼度 | 回答にソースURL・取得日時・信頼度・AI生成フラグを付与 |
| 人間承認 | 業務判断への反映は承認フロー必須（docs/10 AIガバナンス準拠） |
| 権限制御 | モデル・プロンプト・入出力をロール別に制御 |
| プロンプトインジェクション対策 | 外部データを指示として扱わない分離・サニタイズ・テスト |
| 個人・機密情報保護 | 個人情報を含むデータをAI入力へ送らないフィルタ |
| 監査 | モデル・プロンプト・入出力・利用者・時刻・コストを監査ログ化 |
| 誤判定時の責任分界 | 「AIは参考情報・最終判断は人」を利用規約・画面へ明記 |
| 予算上限・停止 | 月次上限・アラート・即時停止スイッチ・利用量レポート |
