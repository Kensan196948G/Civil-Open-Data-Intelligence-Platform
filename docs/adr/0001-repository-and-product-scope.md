# ADR 0001: Global Civil API CatalogをCODIPの台帳モジュールとして扱う

## ステータス

採用

## 背景

関連案として `Global-Civil-API-Catalog` と `Civil-Open-Data-Intelligence-Platform` が存在する。前者はデータソース、API仕様、利用条件、更新頻度を登録するカタログ機能に近い。後者はカタログに加えて、データ取得、標準化、検索、地図、後続APIまで扱う上位基盤である。

## 判断

`Global-Civil-API-Catalog` 相当の機能を、CODIPの「データソース・カタログ管理モジュール」として吸収する。

既存リポジトリを残す場合は、調査・検証用リポジトリとして位置付ける。

| リポジトリ | 位置付け |
| --- | --- |
| `Global-Civil-API-Catalog` | API調査、接続実験、仕様確認 |
| `Civil-Open-Data-Intelligence-Platform` | 正式なアプリケーションと共通データ基盤 |

## 理由

1. 台帳と取得・標準化・検索を分離しすぎると、仕様変更時の追跡が難しくなる。
2. 後続システムはCODIPの共通APIを見ればよく、公開元APIを個別に追う必要がなくなる。
3. データ品質、取得ログ、利用条件を同じ場所で管理できる。

## 影響

| 影響 | 内容 |
| --- | --- |
| 良い影響 | 正本がCODIPに集約される |
| 注意点 | 調査用リポジトリとの差分管理が必要 |
| 実装影響 | 台帳モジュールをCODIPの中核機能として扱う |
